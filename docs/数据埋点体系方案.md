# 数据埋点体系方案

## 一、埋点目标与价值

### 核心目标
- **了解用户行为**：用户如何使用产品，哪些功能受欢迎
- **优化产品决策**：数据驱动的功能迭代和优化
- **监控系统健康**：性能问题、错误追踪、稳定性监控
- **分析转化漏斗**：发现流失环节，提升转化率

### 数据价值
- 产品经理：功能使用率、用户路径、A/B 测试
- 运营团队：活跃度、留存率、转化率
- 开发团队：性能监控、错误追踪、稳定性
- 管理层：核心指标看板、业务增长趋势

---

## 二、埋点分类与设计

### 2.1 埋点类型

**1. 页面埋点（Page View）**
- 页面访问（PV）
- 独立访客（UV）
- 页面停留时长
- 跳出率

**2. 事件埋点（Event Tracking）**
- 点击事件（按钮、链接）
- 表单交互（填写、提交）
- 媒体交互（播放、暂停、拖动）
- 自定义业务事件

**3. 转化埋点（Conversion）**
- 注册转化
- 购买转化
- 功能激活
- 关键路径完成

**4. 性能埋点（Performance）**
- 页面加载时间
- 接口响应时间
- 资源加载耗时
- Core Web Vitals

**5. 错误埋点（Error）**
- JavaScript 错误
- 接口请求失败
- 资源加载失败
- 崩溃与卡顿

## 三、埋点方案选型

### 3.1 工具对比

| 工具 | 类型 | 优势 | 劣势 | 适用场景 |
|------|------|------|------|----------|
| **Google Analytics 4** | 免费 | 功能全面、生态成熟 | 国内访问慢、学习曲线 | 海外业务、预算有限 |
| **神策数据** | 付费 | 国内专业、支持好 | 成本高 | 中大型企业 |
| **友盟+** | 免费+付费 | 国内生态、移动端强 | 功能相对简单 | 移动应用为主 |
| **Mixpanel** | 付费 | 用户行为分析强 | 国内访问慢、贵 | 重度分析需求 |
| **Plausible** | 付费 | 隐私友好、轻量 | 功能相对基础 | 注重隐私 |
| **Sentry** | 免费+付费 | 错误监控专业 | 主要监控用途 | 错误追踪 |

### 3.2 推荐方案

**方案 A：预算充足**
- 业务埋点：神策数据 / Mixpanel
- 错误监控：Sentry
- 性能监控：DataDog / New Relic

**方案 B：预算有限**
- 业务埋点：Google Analytics 4
- 错误监控：Sentry（免费版）
- 性能监控：Lighthouse CI + 自建

**方案 C：自建方案**
- 埋点 SDK：自研
- 数据上报：自建服务
- 数据分析：ClickHouse + Grafana

## 四、埋点技术实现

### 4.1 SDK 统一封装

```typescript
// lib/tracker.ts
import Analytics from 'analytics';
import googleAnalytics from '@analytics/google-analytics';

class Tracker {
  private analytics;

  constructor() {
    this.analytics = Analytics({
      app: 'app-name',
      plugins: [
        googleAnalytics({
          measurementIds: ['G-XXXXXXXXXX'],
        }),
        // 可以添加多个插件
      ],
    });
  }

  // 页面浏览
  pageView(url: string, properties?: Record<string, any>) {
    this.analytics.page({ url, ...properties });
  }

  // 事件追踪
  track(eventName: string, properties?: Record<string, any>) {
    this.analytics.track(eventName, properties);
  }

  // 用户识别
  identify(userId: string, traits?: Record<string, any>) {
    this.analytics.identify(userId, traits);
  }
}

export const tracker = new Tracker();
```

### 4.2 自动页面埋点

```typescript
// app/layout.tsx
'use client';

import { useEffect } from 'react';
import { usePathname, useSearchParams } from 'next/navigation';
import { tracker } from '@/lib/tracker';

export function AnalyticsProvider({ children }) {
  const pathname = usePathname();
  const searchParams = useSearchParams();

  useEffect(() => {
    const url = pathname + (searchParams?.toString() ? `?${searchParams}` : '');
    
    tracker.pageView(url, {
      title: document.title,
      referrer: document.referrer,
    });
  }, [pathname, searchParams]);

  return <>{children}</>;
}
```

// lib/performance-tracker.ts
export function trackWebVitals() {
  if (typeof window === 'undefined') return;

  // Core Web Vitals
  import('web-vitals').then(({ onCLS, onFID, onLCP, onFCP, onTTFB }) => {
    onCLS((metric) => {
      tracker.track('performance_metric', {
        metric_name: 'CLS',
        value: metric.value,
        rating: metric.rating,
      });
    });

    onFID((metric) => {
      tracker.track('performance_metric', {
        metric_name: 'FID',
        value: metric.value,
        rating: metric.rating,
      });
    });

    onLCP((metric) => {
      tracker.track('performance_metric', {
        metric_name: 'LCP',
        value: metric.value,
        rating: metric.rating,
      });
    });
  });
}

// 接口性能监控
export function trackApiPerformance(url: string, duration: number, status: number) {
  tracker.track('api_performance', {
    url,
    duration,
    status,
    success: status >= 200 && status < 300,
  });
}

## 五、埋点规范设计

### 5.1 命名规范

**事件命名**：`动作_对象_描述`
```
✅ 推荐：
- button_click_submit
- page_view_home
- form_submit_register
- video_play_tutorial

❌ 避免：
- click
- submit
- view
- 登录按钮点击
```

**属性命名**：小写字母 + 下划线
```typescript
// ✅ 推荐
{
  user_id: '123',
  page_title: 'Home',
  button_type: 'primary',
  product_id: 'ABC123',
}

// ❌ 避免
{
  userId: '123',  // camelCase
  PageTitle: 'Home',  // PascalCase
  'button-type': 'primary',  // kebab-case
}
```

## 六、数据隐私与合规

### 6.1 用户隐私保护
- **用户同意**：首次访问显示隐私政策和 Cookie 同意
- **数据脱敏**：不采集敏感信息（密码、身份证、手机号完整信息）
- **匿名化**：支持匿名追踪模式
- **数据删除**：用户请求时可删除个人数据

### 6.2 Cookie & 本地存储

### 6.3 合规要求
- **GDPR**（欧盟）：用户同意、数据可携带、删除权

## 九、最佳实践

### 9.1 性能优化
- **异步上报**：不阻塞主线程
- **批量上报**：合并请求，减少网络开销
- **失败重试**：网络异常时重试机制
- **采样上报**：高频事件按比例采样

```typescript
class Tracker {
  private queue: Event[] = [];
  private batchSize = 10;
  private flushInterval = 5000;

  track(eventName: string, properties?: any) {
    this.queue.push({ eventName, properties, timestamp: Date.now() });
    
    if (this.queue.length >= this.batchSize) {
      this.flush();
    }
  }

  private flush() {
    if (this.queue.length === 0) return;
    
    // 批量上报
    fetch('/api/analytics', {
      method: 'POST',
      body: JSON.stringify(this.queue),
      keepalive: true, // 页面关闭时也能上报
    });
    
    this.queue = [];
  }
}
```

### 9.2 数据质量
- **数据验证**：上报前校验数据格式
- **去重处理**：避免重复上报
- **异常过滤**：过滤明显异常数据
- **版本管理**：埋点版本与代码版本对应

### 9.3 团队协作
- **埋点文档**：维护统一的埋点文档
- **评审机制**：新增埋点需要评审
- **变更通知**：埋点修改通知相关方
- **定期清理**：删除无用埋点

## 十、常见问题

### Q1: 埋点会影响性能吗？
**A:** 设计良好的埋点系统影响微乎其微（< 100ms）。关键是异步上报、批量处理、避免阻塞。

### Q2: 需要埋多少点？
**A:** 遵循"关键指标必埋，细节按需"原则。核心转化路径、重要功能必埋，非关键功能可选。

### Q3: 如何保证数据准确性？
**A:** 测试验证、数据校验、异常监控、定期抽查。

### Q4: 自建还是第三方？
**A:** 预算有限或数据安全要求高选自建；否则第三方更省心。

### Q5: 多久分析一次数据？
**A:** 日常数据每日查看，深度分析每周/每月，重大决策前专项分析。
